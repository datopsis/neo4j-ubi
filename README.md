# Neo4j Community on UBI 9

Security-oriented Neo4j Community **2026.10.2**, Temurin JRE **25.0.5+8**, and
Red Hat UBI **9.8 Micro**. This is an unreleased first increment, not a supported
or certified distribution. The bundled vulnerable Parquet Jackson jar is
[deliberately excluded](docs/KNOWN-FINDINGS.md); Parquet import is unavailable.
Repository packaging is Apache-2.0; Neo4j Community
is **GPL-3.0-or-later**. See [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES).

The runtime uses UID 10001, has no package manager, and requires no Linux
capabilities. HTTP listens on 7474 and Bolt on 7687. No Enterprise components
or commercial licence acceptance are included. Optional plugin bundles are
excluded; arbitrary plugins and arbitrary Neo4j configuration are outside this
initial fixed profile.

The supported scope of this development profile is the console server,
authenticated Cypher reads/writes and durable data across restarts with the
restrictions below. `parquet-jackson-1.18.1.jar` is removed after bundle
verification to eliminate four fixed High Jackson findings. Offline Parquet
import (`neo4j-admin database import full --input-type=parquet`) is unavailable.
Admin import/export workflows, Parquet metadata/key tooling, APOC-style
procedures and custom plugins are unsupported. The entrypoint permits only
`console`. Other jars and the server's top-level Jackson are unchanged. Every
Neo4j upgrade must revisit the exclusion and pass both native CI suites.

## Build and checks

Tools: Python 3.11+, curl, GnuPG, RPM/rpmkeys, and Docker or Podman. Acquisition
requires network access. The image assembly itself runs without network access
or dependency resolution. Tools installed on the host are not image contents.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --require-hashes --only-binary=:all: -r .github/requirements/pre-commit.txt
pre-commit run --all-files
python -m unittest discover -s tests -p 'test_*.py' -v
# Use amd64 on an x86_64 host, arm64 on an aarch64 host.
CONTAINER_RUNTIME=docker bash scripts/build.sh arm64
ARCHITECTURE=arm64 CONTAINER_RUNTIME=docker python3 tests/runtime.py
```

CI uses native `ubuntu-24.04` and `ubuntu-24.04-arm` Docker hosts. Podman is an
available build/runtime command interface, not yet a qualified deployment.
Runtime tests require permission to set the test credential's ownership for
Docker. A sandbox that denies user namespaces cannot supply container evidence;
local policy tests do not substitute for native CI.

## Run with explicit storage and credentials

Prepare a durable directory owned by UID 10001 (mode 0700), and a read-only
credential file owned by UID 10001 or readable by its group 0 (mode 0400 or
0440). The credential is one line of at least 16 printable ASCII characters,
maximum 1024 bytes including an optional final newline. Supply it from your
secret manager; no password is shown or generated by the image.

Set `NEO4J_DATA_DIR` and `NEO4J_PASSWORD_FILE` to their absolute host paths:

```sh
: "${NEO4J_DATA_DIR:?set the prepared durable directory}"
: "${NEO4J_PASSWORD_FILE:?set the operator credential file}"
docker run --name neo4j --read-only --cap-drop=ALL \
  --security-opt=no-new-privileges --memory=2g --cpus=2 --pids-limit=256 \
  --tmpfs=/tmp:rw,noexec,nosuid,nodev,size=256m,mode=1777 \
  --tmpfs=/run/neo4j:rw,noexec,nosuid,nodev,size=64m,uid=10001,gid=0,mode=0700 \
  --mount "type=bind,source=$NEO4J_DATA_DIR,target=/data" \
  --mount "type=bind,source=$NEO4J_PASSWORD_FILE,target=/run/secrets/neo4j-password,readonly" \
  -p 127.0.0.1:7474:7474 -p 127.0.0.1:7687:7687 \
  localhost/neo4j-ubi:dev
```

The initial account name is `neo4j`. The mounted credential initializes a new
database, without putting the password in process arguments or environment.
Every authenticated start requires the file, including restarts. On existing
data it does **not** reset or rotate passwords: use Neo4j's authenticated user
management, then update the secret manager. Back up the entire `/data` volume;
never remove it to rotate credentials. Stop with a 45-second grace period.

Authenticated initialization writes a non-secret marker in `/data`. Data first
created with the no-auth opt-out, or an imported volume without that marker,
is refused when authentication is enabled. This prevents re-enabling upstream
default credentials. Migrating such data requires a separately qualified
authentication recovery procedure; do not fabricate the marker.

| Path | Mount and purpose |
| --- | --- |
| `/data` | Explicit writable durable bind/named volume; database, auth, transactions |
| `/run/neo4j` | Writable UID-10001 tmpfs; generated configuration, transient bootstrap argument file, runtime state |
| `/tmp` | Writable tmpfs; JVM and native temporary files |
| `/run/secrets/neo4j-password` | Read-only operator credential file |
| Everything else | Read-only image filesystem |

There is deliberately no `VOLUME` instruction: missing mounts fail instead of
silently allocating anonymous storage. The guard rejects `/data` tmpfs, but
cannot prove the durability of a remote filesystem or underlying host disk.
The operator owns storage durability, backup, network isolation and host security.
Logs go to stdout. The healthcheck tests HTTP discovery, not authenticated query
readiness; CI also executes real authenticated transactions and persists a node.

## Configuration and explicit opt-out

- `NEO4J_UBI_PASSWORD_FILE`: absolute credential path; default above.
- `NEO4J_UBI_HEAP`: initial/max Java heap, default `512m`.
- `NEO4J_UBI_PAGECACHE`: page cache, default `256m`.
- `NEO4J_UBI_ALLOW_NO_AUTH=true`: deliberately disables authentication, emits a
  warning on every startup, and requires omitting `NEO4J_UBI_PASSWORD_FILE`.
  Use only on an isolated disposable test deployment. It leaves `/data` mandatory.

Memory values accept positive integers followed by `m` or `g`. Unknown
`NEO4J_*` variables (including upstream Docker's `NEO4J_AUTH`) and JVM injection
variables fail with a diagnostic. There is no command expansion or configuration
passthrough in this increment. CSV file imports, unrestricted procedures and
usage reporting, Fleet Manager/discovery and forwarded-header trust are disabled.

This initial profile serves plaintext HTTP/Bolt. Bind to host loopback as shown;
remote access requires an operator-managed encrypted tunnel or TLS gateway and
network policy. Native TLS configuration and deployment qualification are roadmap
work. Do not expose these listeners directly to untrusted networks.

## Inputs and evidence

[artifacts/neo4j.lock.json](artifacts/neo4j.lock.json) pins both UBI indexes and
their amd64/arm64 manifests, Neo4j's published SHA-256, Temurin's version,
archive/signature hashes and signer, and every added RPM's NEVRA/SHA-256.
The extracted bundle manifest is also pinned and rechecked during assembly.
Neo4j tarball acquisition is **digest only**, not signature-authenticated.
Temurin GPG and Red Hat RPM publisher signatures are verified. See
[artifact acquisition](docs/ARTIFACT-ACQUISITION.md).

```sh
python3 scripts/artifacts.py refresh
# For a deliberate Neo4j upgrade:
# python3 scripts/artifacts.py refresh --version <upstream-version>
diff -u artifacts/neo4j.lock.json candidates/neo4j.lock.json
```

Refresh proposes current UBI 9.8, JVM 25 and RPM inputs for the selected Neo4j
version; it does not guess a Neo4j upgrade. Review the candidate, update the
Containerfile base defaults and notices, then rerun all checks. The read-only
`update-locks.yml` uploads candidates and a diff; it cannot commit or open PRs.
Python tool lock regeneration is documented in the `.in` file. Every dependency,
including transitive dependencies and ShellCheck, is hash pinned in `.txt`.

CI retains per-architecture SPDX SBOMs, complete Trivy/Grype JSON reports and
runtime output for 14 days. Both scanners report all findings. A separate tested
gate **blocks fixed High/Critical non-RPM findings and RPM fixes installable
from the build's UBI BaseOS repositories**. Only successful negative repository
queries defer RPM fixes, with vendor versions shown in the job summary. Query,
version and identity errors fail closed; missing/malformed reports fail too.
Unfixed and deferred findings remain visible, without ignore lists. Scheduled
native CI rechecks every six hours; a trusted-main-only job tracks changes to
the deferred set in one issue. See [SECURITY.md](SECURITY.md).

## Repository layout

- `Containerfile`, `container/`: offline image assembly and guarded runtime.
- `artifacts/`: lock and public publisher keys.
- `scripts/`: acquisition, lock proposals, build, lint and vulnerability gate.
- `tests/`: policy regressions and real native server/runtime tests.
- `.github/`: hash-locked tooling and read-only CI/update workflows.
- `docs/`: [ordered roadmap](docs/ROADMAP.md), [version rules](docs/VERSION.md), acquisition and verification boundaries.

The sibling Datopsis UBI repositories informed this layout. The draft
container-hardening criteria are reference material only. There is no dependency
on that repo, no conformance call, and no release-eligible gate. No workflow
publishes or signs an image; tags trigger no publishing.
